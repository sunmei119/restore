# 应用中心重构 - 设计基线

## 一、文档概述

本设计基线覆盖应用中心重构的全部一期内容，基于对齐稿和原始需求文档、原型，提供可进入研发的完整设计定义。

**设计范围**：应用管理（申请/上架/范围/分类/审批/标签）、平台管理（应用统计）、订单管理（套餐授权/接收记录/试用记录）、门户端（教育服务中心/购买页/我的空间/我的应用中心/我的订单）、移动端门户（首页/班级/消息/我的）。

## 二、范围与建设方式

### 建设方式：hybrid（混合建设）

- **复用**：商城支付流程、组织中心组织架构查询、数据字典
- **新建/改造**：应用管理全流程、平台管理后台、教育服务中心嵌入页面
- **对接**：商城页面嵌入（去地址栏/搜索/标签栏）、组织中心机构查询

### 系统外部依赖

| 外部系统 | 交互内容 | 交互方式 |
|---------|---------|---------|
| 组织中心 | 机构列表、组织架构树、机构/学校层级 | API |
| 商城系统 | 付费应用商品详情展示、支付流程 | 内嵌页面 + API |
| 第三方应用系统 | 生态应用对接、suiteID 验证 | API |
| 数据字典 | 分类等字典项 | API |
| 消息中心 | 下线通知 | API |

### 模块详述

#### 应用管理模块

职责：覆盖机构内应用从申请、审批、上架、范围配置到分类标签的全生命周期管理。包含三个子模块：应用上架管理（P01~P05）、上架范围管理（P07~P08）、应用分类管理（P09）、应用审批管理（P10~P11）、标签管理（P12）；另含超管跨机构视角的全平台应用治理页（P06）。

包含页面：P01 应用申请管理页、P02 应用申请编辑页、P02b 应用详情页、P04 应用上架管理页、P04b 应用安装列表页、P05 应用上架配置页、P06 全平台应用页、P07 上架范围管理页、P08 上架范围编辑页、P09 应用分类管理页、P10 应用审批列表页、P11 应用审批操作页、P12 标签管理页。

#### 平台管理模块

职责：覆盖运营统计。platform_admin / platform_operator 查看全平台数据；tenant_admin（机构管理员）查看本机构数据（本机构创建/管理的应用及本机构范围内的使用数据）。

包含页面：P17 应用统计看板页。

#### 订单管理模块

职责：覆盖订单套餐授权、订单记录（应用购买的订单）和试用套餐的记录管理。

包含页面：P18 订单套餐授权管理列表页、P19 订单记录管理列表页、P20 试用订单记录页、P26 应用套餐配置列表页。

#### 门户端模块

职责：覆盖最终用户可见的教育服务中心、应用购买、个人管理中心。

包含页面：P21 教育服务中心页、P22 桂教通门户页、P24 我的应用中心页、P25 我的订单页。

#### 移动端门户模块

职责：覆盖机构管理员在移动端（390×844 视口）浏览、搜索、安装应用及查看班级、接收消息的入口，与 PC 端门户端模块并存，不改动 PC 端逻辑。采用亮色主题，底部 Tab 为首页、应用、班级、消息、我的。

包含页面：P21-M 移动端门户页。

## 五、核心业务流程

### 流程一：应用上线申请审批流程

**链路**：机构管理员提交申请 → 桂教通超级管理员审批 → 审批通过/驳回

**阶段一：机构管理员提交上线申请**
1. 管理员在应用申请管理页，对已创建的应用（app.status = offline）点击"上线"。
2. 进入 P02b 应用详情页（上线申请模式），确认应用信息完整。
3. 点击底部"确认上线"按钮，系统生成 review 记录（type=上线，status=pending），toast「上线申请已提交，待桂教通超级管理员审批」，返回 P01 列表。
4. 桂教通超级管理员在应用审批列表页收到该待审批记录。

**阶段一 · 下线路径**（与上线审批并行的独立分支）：
1a. 管理员对 app.status = online 且 app.listing_status = unlisted 的应用点击"下线"。
1b. 弹窗提示「确定要下线该应用吗？」，确认后 app.status = offline，无需生成审批记录、无需审批。
1c. 已上架（listing_status = listed）应用不允许下线，"下线"按钮直接隐藏。

**阶段二：桂教通超级管理员审批**
6. 桂教通超级管理员打开审批详情页，查看应用全部信息。
7. 桂教通超级管理员选择"通过"或"驳回"。
8. 驳回时需填写驳回原因，审批记录状态变为"审批驳回"，应用状态变为"已驳回"（app.status = rejected），机构管理员可在 P02b 管理模式查看审批信息（申请时间、申请人、审批人、审批时间、审批结果、审批意见），修改后可重新提交上线申请（重新提交后 app.status 回到 offline）。
9. 通过后审批记录状态变为"审批通过"，应用状态变为"已上线"，进入机构管理员的应用上架管理列表（P04），状态为未上架（listing_status = unlisted）。

**阶段三：审批后处理**
10. 审批通过的应用可进入上架流程。
11. 审批驳回的应用，管理员修改后可重新提交上线申请。
12. 审批记录永久保留，包含审批结果、审批时间、审批人、备注。

**异常处理**：
- 审批期间网络中断，当前审批结果不落库，已填写意见保留并允许重试
- 审批中应用不可编辑基本信息

### 流程二：应用上架 → 安装流程

**链路**：机构管理员上架应用 → 配置上架范围 → 用户安装

**阶段一：机构管理员上架应用**
1. 管理员在应用上架管理页，对已上线的应用点击"上架"。
2. 进入上架范围配置页。
3. 配置上架范围：选择"全平台"或"按范围选择"。
4. 全平台：平台所有机构及用户可见。
5. 按范围：输入名称查询范围列表并选择；P05 展示上架承诺书文案、链接及勾选（未勾选时"确认上架"置灰），勾选后方可确认。
6. 点击确认后上架成功，上架状态变为"已上架"。

**阶段二：用户查看安装范围与安装/卸载**
7. 管理员在 P04 应用上架管理中，点击行内"上架范围"超链接（多个范围可点选任一），跳转 P04b 应用安装列表页。
8. P04b 展示该范围覆盖的所有机构（含教育局机构与学校），支持按机构名称/机构 ID/安装状态查询与重置；页面根据当前应用的应用属性自动展示对应的安装流程说明（原生应用 / 低代码应用），安装状态分三态：安装成功、安装失败（应用中心或低代码平台安装失败，均展示安装失败原因）、未安装。
9. 单个安装：点击行尾"安装"（未安装）或"重试"（安装失败）按钮，弹窗提示"是否确认将【应用名称】应用在【机构名称】安装？"，点击"确认安装"后本机构安装成功；点击"取消"不安装。
10. 单个卸载：点击行尾"卸载"按钮，弹窗提示"是否确认将【应用名称】应用从【机构名称】卸载？"，点击"确认卸载"后本机构卸载成功；点击"取消"不卸载。
11. 全部安装：点击查询区"全部安装"按钮，弹窗提示"是否确认将【应用名称】应用安装到全部机构/学校？"，点击"确认全部安装"后台执行全量安装；点击"取消"不安装。
12. 全部卸载：点击查询区"全部卸载"按钮，弹窗提示"是否确认将【应用名称】应用从所有机构/学校卸载？"，点击"确认全部卸载"后台执行全量卸载；点击"取消"不卸载。
13. 终端用户也可在教育服务中心或应用范围中浏览应用并自助安装。

**阶段三：应用下架**
14. 在 P04 点击"下架"：二次提醒"确认要下架 XXX 吗？下架后全区用户将无法使用此应用，已安装的应用不会被卸载"，确认后下架成功，app.listing_status = dismissed（已下架）。

### 流程三：教育服务中心上架流程

**链路**：平台运营拉取应用 → 配置上架 → 教育服务中心可见

1. 平台运营在应用配置管理列表页，从平台内已上架各范围同步应用信息。
2. 同步成功后提示"同步应用成功"。
3. 对已同步的应用，运营配置上架至教育应用服务中心。
4. 配置编辑：基础属性（Logo/名称/suiteID/介绍从上游带过来，secret 可修改）、分类属性（分类）、对接配置（跳转类型/跳转限制/各端跳转地址/小程序APPID）、安装计费配置（厂商/机构/收费类型/跨机构设置）。
5. 配置完成后点击上架，上架成功后教育服务中心可见。
6. 已上架的应用，运营可下架（二次提醒："是否确定下架？"）。

### 流程四：应用付费购买流程

**链路**：用户浏览应用 → 判断免费/付费 → 付费应用购买（对接惠缴费）

1. 用户在教育服务中心或我的应用中心点击应用。
2. 免费应用直接打开使用。
3. 付费应用打开应用购买详情页（内嵌商城商品页，去掉地址栏/搜索/标签栏与加入购物车功能）。
4. 判断应用是否可试用：
   - 可试用：详情页展示"免费试用"与"立即购买"两个按钮；
   - 不可试用：仅展示"立即购买"按钮。
5. 点击"免费试用"：生成一条试用订单记录，应用进入试用可用状态。
6. 点击"立即购买"：打开订单确认 & 开票信息填写界面，发票信息录入右上角提供"历史发票记录"入口，可查看当前人员历史发票记录，选择一条后自动回填发票信息；用户也可手动填写发票信息后点击"提交订单"，跳转至付费界面。
7. 付费界面展示与惠缴费对接的支付二维码，手机扫码唤起惠缴费半屏支付。
8. 支付成功：PC 端同步提示"支付成功"；支付失败：提示失败并展示"返回订单"按钮，点击返回我的订单界面。

**支付结果同步机制（PC 端同步提示）**：
- 惠缴费支付回调：手机扫码完成支付后，惠缴费异步回调平台后端（回调含签名校验、幂等处理），后端校验通过后更新订单状态为已支付，并触发订单记录生成、套餐授权写入、接收记录生成等后续动作。
- PC 端状态轮询：支付界面展示二维码后，PC 端每 3 秒轮询一次订单支付状态接口；检测到已支付即停止轮询，同步提示"支付成功"并进入成功页；检测到支付失败则提示失败并展示"返回订单"按钮；超过支付有效期（15 分钟，与二维码有效期一致）仍未支付则提示支付超时、二维码失效，可点击"刷新二维码"。
- 明确不做：不采用 WebSocket/SSE 服务端推送。理由：惠缴费回调仅到达后端、无法直达浏览器；扫码支付页面长期停留且状态变化低频，3 秒轮询足够及时，实现简单可靠，无需引入长连接组件。

> 说明：本流程支付环节通过对接惠缴费完成，属于新增支付集成；商城现有自有支付流程保持不变（见 align「明确不做：商城支付流程改造」）。

## 九、规则与状态定义

### 9.1 应用（Application）状态机

应用有两个维度的独立状态：**上下线状态（app.status）** 和 **上架状态（app.listing_status）**。

#### 维度一：应用上下线状态

| 状态 | 含义 | 操作人 | 触发动作 | 下一状态 | 限制条件 |
|------|------|--------|----------|----------|----------|
| offline | 未上线，不可上架 | tenant_admin | 提交上线审批 | online / rejected | 审批通过变为 online；审批驳回变为 rejected |
| offline | 未上线，不可上架 | platform_admin | P02b 上线申请模式提交（免审批） | online | 提交即上线，不生成 review 记录 |
| rejected | 已驳回 | platform_admin | 重新提交上线申请（免审批） | online | 直接置 online，不生成 review 记录 |
| rejected | 已驳回，上线申请被驳回，不可上架 | tenant_admin | 重新提交上线审批 | offline（审批中）/ online | 重新提交后回到 offline（列表展示待审批）；审批通过变为 online；P02b 管理模式展示审批信息 |
| online | 已上线，可进行上架 | tenant_admin | 下线 | offline | 未上架时允许下线；已上架时隐藏下线按钮 |

#### 维度二：应用上架状态

| 状态 | 含义 | 操作人 | 触发动作 | 下一状态 | 限制条件 |
|------|------|--------|----------|----------|----------|
| unlisted | 未上架，范围中不可见 | tenant_admin | 上架配置 | listed | app.status 必须为 online；需配置上架范围；须勾选上架承诺书（未勾选时确认上架置灰） |
| listed | 已上架，范围中可见 | tenant_admin | 下架 | dismissed | 二次确认："下架后全区用户将无法使用此应用，已安装的应用不会被卸载" |
| listed | 已上架，范围中可见 | platform_admin | 强制下架（P06） | dismissed | 二次确认："确定要强制下架【{app.name}】吗？下架后该应用在【{app.tenant_name}】的上架列表将变为已下架状态，已安装的应用不卸载。"；仅超管可操作；写 OperationLog（force_delist） |
| dismissed | 已下架，范围中不可见，已安装应用不受影响 | tenant_admin | 上架配置 | listed | 可重新上架，且重新上架时保留原上架范围（P05 默认回填下架前的范围配置） |

业务规则：
- 应用必须先上线（online）后才可上架（listed）
- 已上架的应用不允许直接下线（下线按钮隐藏）
- 必须先下架（dismissed 或 unlisted）后方可下线（offline）
- 编辑修改不改变 app.status，仅以 editState 标记：未上线应用编辑保存直接生效（不生成审批记录）；已上线/已上架应用编辑保存后 editState = pending_submit（修改待提交，列表标签"修改待提交"），重新提交上线申请后 editState = pending_review（修改待审批，列表标签"修改待审批"），审批通过后合并修改并清除标记，驳回后回到 pending_submit

### 9.2 审批记录（ReviewRecord）状态机

| 状态 | 含义 | 操作人 | 触发动作 | 下一状态 | 限制条件 |
|------|------|--------|----------|----------|----------|
| pending | 待审批（上线） | tenant_admin | 提交上线申请 | — | 仅 app.status = offline / rejected 且无待提交修改时生成；app 信息完整方可提交 |
| pending | 待审批（修改） | tenant_admin | 已上线 / 已上架应用编辑保存后，重新提交上线申请 | — | 编辑保存本身不生成记录，提交上线申请时才生成；审批通过前对外仍展示旧值 |
| pending | | platform_admin（桂教通超级管理员） | 审批通过 | approved | — |
| pending | | platform_admin（桂教通超级管理员） | 驳回 | rejected | 驳回原因必填 |
| approved | 审批通过；上线类型进入上架列表，修改类型的新值此时生效 | — | — | — | 终态；上线：app.status 变为 online 并进入上架列表（listing_status = unlisted）；修改：保持原有上线 / 上架状态，不重复进入上架列表 |
| rejected | 审批驳回 | tenant_admin | 重新提交 | pending | 上线类型 app.status 变为 rejected；修改类型修改内容不生效，回到 pending_submit 可再次提交 |

业务规则：
- 上线类型审批通过后应用状态自动变为 online，并进入机构管理员的应用上架管理列表（未上架）
- 修改类型审批通过后修改内容才生效，应用保持原有上线 / 上架状态，不重复进入上架列表
- 审批驳回后上线类型应用状态变为 rejected（已驳回），申请人修改后可重新提交上线申请；修改类型驳回后修改内容不生效且保留待提交内容，可调整后重新提交
- 审批记录永久保留，不可删除
- 桂教通超级管理员提交上线申请时不生成 review 记录，直接置 app.status = online（审批为超管专属操作，不存在自我审批）

| pending | 待支付 | 系统生成 | 用户下单 | — | 用户在商城完成下单时生成；需关联有效的套餐授权配置 |
| pending | | 商城系统 | 支付回调 | paid | 商城支付完成回调后自动变更 |
| pending | | 系统 | 超时取消 | cancelled | 超过支付有效期未支付时自动变更 |
| paid | 已支付 | 系统 | 授权到期 | expired | 授权有效期到达后自动变更（套餐有效期到期） |
| expired | 已过期 | — | — | — | 终态；授权有效期到达后从 paid 自动流转 |
| cancelled | 已取消 | 用户 | 取消订单 | — | 仅 pending 状态下可取消；paid 状态不可取消 |
| paid | 已支付 | tenant_admin（机构管理员） | 申请退款 | refund_pending | 仅 paid 状态可申请；退款工单提交后同步至桂教通超级管理员待审批队列 |
| refund_pending | 退款中 | platform_admin（桂教通超级管理员） | 审批通过 | refund_success | 审批意见选填；通过后触发原路退款，订单状态置为退款成功 |
| refund_pending | 退款中 | platform_admin（桂教通超级管理员） | 审批驳回 | refund_rejected | 驳回原因必填；驳回后订单回到 paid，可重新发起退款 |
| refund_rejected | 退款驳回 | tenant_admin（机构管理员） | 重新申请退款 | refund_pending | 修改后可重新发起退款申请 |

业务规则：
- 订单状态迁移：pending → paid（支付成功）/ cancelled（超时或用户取消）
- paid 的订单根据套餐有效期到期后变为 expired
- paid 的订单可由机构管理员发起退款，进入 refund_pending，经桂教通超级管理员审批后迁移至 refund_success / refund_rejected
- 订单状态不可逆（paid 不可回退到 pending）；但退款链路内 refund_pending 可由审批驳回回退至 paid，refund_rejected 可由机构管理员重新发起退款回到 refund_pending
- **退款通过后应用回到购买前状态**：refund_pending 经审批通过（→ refund_success）后，对应应用回到购买前状态——购买前已安装则保持已安装状态，未安装则保持未安装状态，不强制从「我的应用中心」移除；点击应用打开应用详情页（P22），根据安装状态展示「购买/安装」按钮，即整体回到用户购买前的可使用状态；订单保留 refund_success 终态以留痕审计

### 9.8 业务规则

1. **应用创建规则**：应用属性分为原生应用（低代码应用/自建应用/智能体应用）和生态应用（第三方对接），创建时据此展示不同字段。
2. **学段选择规则**：适用机构选择为"学校"时展示适用学段；学段范围模式为单选（所有学段/部分学段），选择"部分学段"时下方展开学段多选（幼儿园/小学/初中/高中/中职/高职/本科/研究生），支持多选必填。
3. **分类删除规则**：有下级分类或分类下有应用时不允许删除，提示用户先处理关联数据。
4. **分类启用/停用规则**：停用时当前分类及下级全部停用；启用时同上；已启用分类不显示删除按钮。
5. **分类编码规则**：同一层级分类名称和分类编码不可重复；最多可建 2 级分类。
6. **标签删除规则**：被应用上架可见范围配置引用的标签不可删除（隐藏删除按钮），应用下架后若标签未被使用可删除；删除后该标签从可见范围中删除，如已上架应用，该标签下用户不可见。
7. **统计规则**：默认展示今日数据，按今日/本周/本月/本年切换；已开通机构数和平台应用数为累计值不随时间切换变化；活跃应用数和应用使用人数按所选时间周期统计。
8. **历史审批记录**：流程保留所有审批记录，包含审批结果、审批时间、审批人、备注，不可删除。
10. **付费购买**：付费应用直接内嵌商城商品详情页，不跳转；去掉浏览器地址栏、搜索、标签栏；去掉加入购物车功能。
11. **SuiteId 生成规则**：应用申请成功（首次保存）后由系统自动配置 app.system_suite_id 与 app.system_suite_key；app.system_suite_id **全局唯一**，创建后**不可修改**、不可重置。
12. **SuiteKey 更新规则**：在 P02b 应用详情页点击 SuiteKey 右侧「更新」按钮，弹出确认框「更新后，原 SecretKey 会在 2 天后失效，请尽快完成相应调整，保证应用的正常使用，是否确定现在更新？」，确认后系统重新生成 app.system_suite_key，同步刷新 app.system_suite_key_updated_at；旧 Key 从更新时刻起保留 **2 天有效期**用于对接方过渡，2 天后自动失效。取消或关闭弹窗不产生任何变更。
13. **应用管理入口跳转规则**：应用申请管理点击「管理」→ 进入 P02b 应用详情页（查看模式）；再由 P02b「修改」按钮进入 P02 编辑模式；P02 底部按钮按模式区分：新建模式为「新建」，编辑模式为「提交」；提交/新建后回到来源页（P02b 或 P01）。
14. **上架配置信息只读规则**：应用上架配置页（P05）中应用基本信息区全部字段均为只读展示，不提供任何编辑入口。
15. **业务应用ID（app.app_id）生成规则**：新增应用时由系统在当前全平台最大业务应用ID基础上 +1 自动生成，全局唯一、不可修改、不可重置；编辑应用时不重新生成。
16. **应用 openId（app.app_open_id）生成规则**：非低代码应用由系统自动生成，长度固定 15，仅支持英文、数字、下划线，全局唯一；低代码应用的 openId 取创建时填写的低代码应用ID（app.lowcode_app_id）。
17. **上架版本号展示规则**：低代码应用展示版本号（单选）；是否跨机构选择"否"时必填，选择"是"时非必填；版本列表依据当前低代码应用ID远程获取；未获取到则提示需先上架到低代码应用市场。
18. **其他机构选择规则**：机构管理员上架时分享范围勾选"其他机构"，展示"其他机构"下拉选择器，采用**精确搜索**——须输入完整机构名称才能检索到对应机构；查询范围为**全平台机构数据**，不限于当前机构管辖范围；支持多选，**最多分享 200 个机构**；下拉框下方以**只读文本区域**按选择顺序回显已选机构名称，不可直接编辑。
19. **全平台应用强制下架规则**：仅桂教通超级管理员在 P06 全平台应用页可对 `listing_status = listed` 的跨机构应用执行"强制下架"；二次确认后目标应用 `listing_status = dismissed`（回到已下架）；已安装应用不卸载（沿用机构下架规则）；同步写入 OperationLog（`log.action = force_delist`、`operator_role = platform_admin`，detail 记录被下架应用、原上架机构、执行人）；对应机构管理员在 P04 应用上架管理页看到该应用状态由"已上架"回落为"已下架"，分享到的其他机构对应的应用状态也改为已下架。
20. **上架范围动态引用规则**：应用上架范围解析出的机构集合为**每次实时解析**（动态引用，非上架时刻快照）。机构、标签、范围任一环节增删，已上架应用的上架范围自动同步更新，无需重新上架、无需重新审核。传播链路：机构新增/删除 → 自动更新引用该机构的标签 → 引用该标签的范围 → 使用该范围的应用上架范围；标签编辑（增删机构）时，引用该标签的所有范围自动同步添加/移除对应机构，使用这些范围的应用上架范围同步更新；范围编辑同理。标签和范围删除前需确认是否被使用：被范围引用的标签不可删除，被应用上架范围引用的范围不可删除。标签/范围内移除机构时，应用上架状态（listing_status）不变，仅上架范围改变，不在范围内的机构不可见该应用；已安装应用不卸载、无需重新审核。
21. **分享停止后不可上架规则**：分享来源应用（`sharedFrom` 有值）若分享方在应用分享管理停止分享当前应用，被分享方侧该记录 `shareRevoked = true` 且 `listing_status = dismissed`（已下架），此后不可重新上架；点击"上架"或提交上架时提示「【分享应用的机构名称】已经停止分享当前应用，当前应用不能上架。」，不进入 P05。停止分享范围含**桂教通平台**时规则一致：桂教通平台侧该应用同样下架且不可重新上架，提示中的机构名称取该应用的分享方机构。已安装应用不卸载。

### 9.9 无状态机实体

以下实体无状态流转，使用属性标记替代状态机：

| 实体 | 说明 |
|------|------|
| 应用分类（Category） | 通过 status 控制启用/停用，无完整状态机 |
| 范围（Zone） | 编辑即生效，无状态流转；被应用上架范围引用的范围不可删除；范围变化动态同步到应用上架范围 |
| 范围标签（Tag） | 增删改即生效，无状态流转；被范围引用的标签不可删除；标签机构变化动态同步到引用范围及应用上架范围 |
| 操作记录（OperationLog） | 仅追加写入，不可变更 |
| 套餐（Package） | 增删改即生效，删除时校验使用状态（被使用不可删除），无状态机 |

- `platform_admin`：可审批所有机构提交的上线申请
- 机构管理员（tenant_admin）无审批权限，应用审批管理模块对其不可见

**应用统计看板页（P17）**：
- platform_admin / platform_operator：统计全平台数据，统计范围仅包含平台应用和平台管理的机构应用，独立机构的应用不计入
- tenant_admin（机构管理员）：统计本机构数据（本机构创建/管理的应用及本机构范围内的使用数据），导出仅限本机构范围
- 导出功能需具备查看权限方可操作

**上架范围编辑页（P08）**：
- `platform_admin`：可编辑全平台自定义范围（新增/修改/删除）
- `tenant_admin`：仅可编辑本机构的自定义范围（新增/修改/删除）
- 默认范围对所有角色只读，无编辑操作

**应用申请编辑页（P02）/ 应用详情页-上线配置（P02b）**：
- 是否平台应用（平台型/非平台型）：仅桂教通超级管理员展示且必填，默认选中非平台型；机构管理员不展示此字段，新增应用固定为非平台型
- 上线配置-跨机构层级、所属机构：仅桂教通超级管理员且低代码应用时展示，且仅"是否跨机构 = 是"时显示；机构管理员展示"是否跨机构"（仅低代码应用）但不展示跨机构层级与所属机构
- 说明：推送地址/TOKEN/EncodingAesKey（是否数据同步=是）、suiteID（应用属性=生态应用）、应用ID（应用属性=低代码应用）、可见性地址（打开方式含对应方式）等为字段间业务联动，非角色权限差异，不在此列

**应用上架配置页（P05）**：
- 范围选择：桂教通超级管理员展示（是否跨机构=否时全平台/按范围，=是时仅按范围）；机构管理员展示（全平台/按范围，必填）；机构管理员且当前机构为学校时不展示该字段，默认上架范围即本校
- 分享范围：仅机构管理员展示（桂教通平台/其他机构多选，学校机构必填、其余非必填）；桂教通超级管理员不展示；勾选"其他机构"后的选择器为精确搜索（须输入完整机构名称）、查询范围为全平台机构数据、最多分享 200 个机构，已选机构名称在下拉框下方只读区域回显；其他机构分享过来的应用不展示该字段（被分享的应用不可再被分享）
