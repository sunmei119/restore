## 一、文档概述

本文档为应用中心重构的产品需求规格说明，面向多机构应用全生命周期管理平台，覆盖机构内应用申请→审批→上架→范围→安装、平台级应用监管与运营统计、教育服务中心集成以及订单管理的完整功能定义。

## 二、范围

### 2.1 建设范围

| 模块 | 包含功能 |
|------|---------|
| 应用管理 | 应用申请管理、应用上架管理、全平台应用（超管专属）、上架范围管理、应用分类管理、应用审批管理、标签管理 |
| 平台管理 | 应用统计 |
| 订单管理 | 订单套餐授权管理、订单记录管理（应用购买的订单）、试用套餐记录管理、应用套餐配置 |
| 门户端 | 教育服务中心（P21 我的空间 / P22 桂教通门户）、应用详情与付费购买（P22 页内视图）、我的空间、我的应用中心、我的订单 |

- 库存管理、对账结算

## 三、业务流程

### 3.1 应用上线申请审批流程

此处管理员指的是桂教通超级管理员，只有桂教通超级管理员具有审批权限。机构管理员新增应用、修改应用、上线申请、桂教通超级管理员审批、结果归档五个环节。应用未上线时修改直接生效、不产生审批流程；已上线或已上架应用的修改需重新提交上线申请，审批通过后才生效。

```mermaid
flowchart TD
    S(["开始：机构管理员新增 / 编辑应用"]) --> D1{"应用当前状态"}
    D1 -->|"未上线 offline"| A1["保存修改直接生效<br/>不生成审批记录"]
    A1 --> E1(["结束：返回应用列表"])
    D1 -->|"已上线 online / 已上架 listed"| A2["修改暂存为「修改待提交」<br/>不生成审批记录"]
    A2 --> B1["提交上线申请<br/>首次上线 / 修改后重新提交"]
    B1 --> B2["生成审批记录<br/>review.status = pending"]
    B2 --> D2{"桂教通超级管理员审批"}
    D2 -->|"驳回（须填写驳回原因）"| R1["review.status = rejected<br/>app.status = rejected"]
    R1 -->|"调整后重新提交"| B1
    D2 -->|"通过"| D3{"是否首次上线"}
    D3 -->|"是"| C1["app.status = online<br/>进入上架列表 listing_status = unlisted"]
    D3 -->|"否"| C2["修改内容此时才生效<br/>保持原有上线 / 上架状态"]
    C1 --> E2(["结束：进入上架流程（3.2）"])
    C2 --> E3(["结束：审批记录留痕"])
```

1. 机构管理员在应用申请管理页对已创建但未上线（app.status = offline）的应用提交上线申请。提交前确认应用基本信息完整，提交后系统生成一条审批记录（review.status = pending）。此时应用不可编辑基本信息。
2. 桂教通超级管理员在审批列表的"待审批"Tab 中看到该记录，查看应用详情后选择"通过"或"驳回"。通过后 app.status 变为 online，应用进入机构管理员的应用上架管理列表（P04），状态为未上架（listing_status = unlisted）；驳回时需填写驳回原因，review.status 变为 rejected，app.status 变为 rejected（已驳回）。
3. 审批通过后应用可进入上架流程。审批驳回后回到上线申请人，修改后可重新提交上线申请（重新提交时 app.status 回到 offline、列表展示待审批）。审批记录永久保留。
4. 已上线 / 已上架应用的修改：机构管理员在 P02 修改已上线（online）或已上架（listed）应用的信息并保存时，系统仅标记为「修改待提交」，不生成审批记录；用户再次点击「提交上线申请」后才生成审批记录（审批记录类型标记为"修改"）。审批通过后修改内容才生效，应用保持原有上线 / 上架状态，不重复进入上架列表；审批驳回时修改不生效，可调整后重新提交。未上线（offline）应用的修改保存后直接生效，不进入审批流程。
5. 修改待提交期间，列表状态标签显示"修改待提交"，操作列提供"提交上线申请"；提交后状态标签显示"修改待审批"，审批通过或驳回后恢复为应用本身的上下线状态。

审批期间网络中断时，当前审批结果不落库，已填写意见保留并允许重试。

下线为独立路径，不经过审批：应用创建人或管理员对 app.status = online 且 app.listing_status = unlisted 的应用点击"下线"，弹窗确认后直接变为 offline；已上架（listing_status = listed）的应用不允许下线，按钮直接隐藏。

### 3.2 应用上架及安装流程

管理员上架应用、配置范围、安装三个环节。

```mermaid
flowchart TD
    S(["开始：已上线且未上架<br/>online + unlisted"]) --> A["P05 配置上架范围<br/>全平台 / 按范围 + 勾选上架承诺书"]
    A --> B["确认上架<br/>app.listing_status = listed"]
    B --> D{"P04b 选择操作"}
    D -->|"单个安装"| I1["安装到指定机构"]
    D -->|"全部安装"| I2["安装到当前列表全部机构"]
    D -->|"下架 / 卸载"| X1["弹窗二次确认"]
    X1 -->|"下架"| X2["下架：用户不可用<br/>listing_status = dismissed"]
    X1 -->|"卸载"| X3["卸载：仅从该机构移除<br/>不删除低代码应用"]
    I1 --> T1{"是否低代码应用"}
    T1 -->|"否"| T2["装到应用中心即对机构可见"]
    T1 -->|"是"| T3["先装应用中心"]
    T3 -->|"失败"| T5["安装失败，可重试"]
    T5 -->|"重试"| T3
    T3 -->|"成功"| T4["再装低代码平台"]
    T4 -->|"失败"| T5
    T4 -->|"两步均成功"| T6(["安装成功"])
    T2 --> T6
    I2 --> T2
```


1. 管理员对已上线（online）且未上架（unlisted）的应用发起上架，进入 P05 配置上架范围（全平台/按范围），勾选上架承诺书后确认，app.listing_status 变为 listed。点击任意上架范围进入 P04b：单个安装为安装到对应机构，全部安装为安装到当前列表所有机构，卸载/全部卸载同理。
2. 安装：非低代码应用只装到应用中心即对机构可见；低代码应用跨机构安装同此流程，不跨机构需先装应用中心（失败则「安装失败」可重试），成功后再装低代码平台（失败同样「安装失败」可重试），两步均成功才算安装成功。
3. 下架和卸载均需二次确认。下架后用户无法使用，卸载仅从指定机构移除，不删除低代码应用。已上架的应用不允许直接下线，必须先下架方可下线。

### 3.3 应用付费购买流程

```mermaid
flowchart TD
    S(["开始：用户在教育服务中心 / 我的应用中心点击应用"]) --> D1{"是否免费应用"}
    D1 -->|"免费"| F1(["直接打开使用（结束）"])
    D1 -->|"付费"| A["进入应用购买详情页"]
    A --> D2{"继续操作"}
    D2 -->|"免费试用"| B1(["生成试用订单记录（结束）"])
    D2 -->|"立即购买"| B2["订单确认 + 开票信息填写<br/>可引用历史发票记录回填"]
    B2 --> C1["提交订单"]
    C1 --> C2["展示惠缴费二维码<br/>手机扫码半屏支付"]
    C2 --> D3{"支付结果"}
    D3 -->|"回调校验通过（已支付）"| E1["后端更新订单状态为已支付"]
    E1 --> E2(["生成订单记录 / 套餐授权 / 接收记录"])
    D3 -->|"失败"| G1(["提示支付失败，可返回订单（结束）"])
    D3 -->|"超时 15 分钟"| G2["提示支付超时，二维码失效"]
    G2 -->|"点击刷新二维码"| C2
    C2 -.->|"PC 端每 3 秒轮询同步支付状态"| D3
```

用户在教育服务中心或我的应用中心点击应用：免费应用直接打开使用；付费应用打开详情界面，可试用时显示「免费试用」+「立即购买」，否则仅显示「立即购买」。
点击免费试用，生成一条试用订单记录；点击立即购买打开订单确认 & 开票信息填写界面，发票信息录入右上角提供"历史发票记录"入口，点击可查看当前人员历史发票记录，选择一条后自动回填至发票信息表单，也可手动填写发票信息；点击提交订单跳转到付费界面，展示跟惠缴费对接的二维码，手机扫码唤起惠缴费半屏支付，支付成功后PC端支付状态同步提示支付成功，支付失败则提示失败，同时出现返回订单的按钮点击返回我的订单界面。PC 端支付状态同步机制：惠缴费完成支付后通过异步回调通知平台后端（回调含签名校验、幂等处理），后端校验通过后更新订单状态为已支付，并触发订单记录、套餐授权、接收记录生成；PC 端支付界面每 3 秒轮询一次订单支付状态接口，检测到已支付即自动提示"支付成功"并进入成功页，检测到失败则提示失败并展示"返回订单"按钮，超过支付有效期（15 分钟，与二维码有效期一致）未支付则提示支付超时、二维码失效可点击"刷新二维码"；不做 WebSocket/SSE 服务端推送

## 四、详细需求说明

### （一）应用管理模块

本模块负责机构内应用的申请、上架、范围配置、分类管理和审批全流程，包含 12 个页面。

#### P01 应用申请管理页

页面由筛选区、结果列表和行内操作组成。筛选区提供应用名称、分类、状态的检索条件；列表按创建时间倒序排列，每页 20 条，展示应用关键信息和状态标签。

（1）查询和查看应用列表

用户进入页面后首先看到当前筛选条件下的应用列表，可以直接判断每条应用的上下线状态和基本属性。列表默认展示：应用 Logo（32×32 圆角图标）、应用名称（超 20 字符末尾截断，悬停显示全文）、应用ID（业务应用ID，置于应用名称之后）、应用openId（仅桂教通超级管理员列展示，置于应用ID之后）、应用分类（一级分类为主标，二级分类为副标灰字）、是否平台应用（平台型/非平台型，仅桂教通超级管理员列展示）、应用属性（完整属性文本，如"原生应用""原生应用/低代码应用""生态应用"）、适用机构（多值枚举展示，如"学校""教育局""超管后台"）、适用学段（多值徽标展示，仅适用机构包含学校时显示）、状态标签（已上线绿色徽标，待审批/修改待审批黄色徽标，修改待提交灰色徽标，已驳回红色徽标，未上线灰色徽标）。

- 修改筛选条件后点击"搜索"，列表按当前条件刷新；点击"重置"清空所有条件恢复默认视图。
- 查询无匹配数据时，列表区域显示"暂无应用"。
- 查询失败时列表区域显示"加载失败，请重试"和刷新按钮。

（2）新增应用

tenant_admin 可在任意状态下点击列表页右上角"新增应用"按钮，跳转 P02 应用申请编辑页（新建模式，底部按钮为"新建"）。

（3）上线应用

仅 app.status = offline 或 app.status = rejected（已驳回）的应用行显示"上线"按钮；已上线 / 已上架应用存在「修改待提交」标记时，操作列改为显示"提交上线申请"按钮。点击后进入 P02b 应用详情页（上线申请模式），页面底部呈现"确认上线"主按钮和"取消"次按钮。

点击"确认上线"前系统校验应用的 Logo、名称、分类等必填项是否完整。校验不通过时顶部红色提示"应用信息不完整，请先完善"，阻止提交。校验通过后系统生成一条审批记录（首次上线 review.type = 上线；存在待提交修改时 review.type = 修改），review.status = pending，review.applicant = 当前登录人；toast 在首次上线时为"上线申请已提交，待桂教通超级管理员审批"，在提交修改时为"上线申请已提交，修改信息待审批通过后生效"，返回列表页。

网络异常导致提交失败时，顶部红色提示"提交失败，请检查网络后重试"。

（4）管理应用

所有状态（已上线/未上线/待审批/已驳回）的应用行均显示"管理"按钮。点击后进入 P02b 应用详情页（管理模式），可查看凭证区和完整信息，并通过"修改"链接跳转 P02 编辑模式。

应用上线申请被驳回（app.status = rejected）或存在修改审批记录（修改待审批 / 已驳回）时，管理模式页面下方额外展示「审批信息」区，字段为：申请类型（上线/修改）、申请时间、申请人、审批人、审批时间、审批结果（驳回红色标签）、审批意见；审批意见缺失时展示"---"。

审批中的应用"管理"按钮不置灰，可正常点击进入 P02b 管理模式；编辑应用与更新 SuiteKey 不受审批状态限制，审批中亦可操作。

（5）下线应用

仅 app.status = online 且 app.listing_status = unlisted 时显示"下线"按钮。已上架（listing_status = listed）时该按钮直接隐藏。

点击"下线"弹出确认框"确定要下线该应用吗？"，确认后 app.status = offline，无需审批，不生成审批记录。下线失败时顶部红色提示"操作失败，请检查网络后重试"。

（6）查看应用（非管理员视图）

其他用户（非 tenant_admin）访问本页时，仅对 app.status = online 的应用行显示"查看"按钮。点击进入 P02b 应用详情页（只读查看模式），无任何操作按钮。

#### P02 应用申请编辑页

页面采用垂直单列表单布局，从上至下依次排列字段。所有标记 * 的字段为必填，未通过校验时对应字段红框提示并阻止提交。

（1）新建应用（新建模式）

从 P01"新增应用"入口进入，页面底部按钮为"新建"和"取消"。表单字段及其规则如下：

| 字段 | 必填 | 控件 | 规则 |
|------|:----:|------|------|
| 应用 Logo | * | 图片上传 | jpg/png/jpeg，推荐 140×140 圆角 24px，≤200KB；缺失提示"请上传应用 Logo"；格式/大小不符时在区域下方红字提示原因 |
| 应用名称 | * | 单行文本框 | 最大 20 字符，右侧实时显示"已输入字数/20"；超限禁止继续输入；名称在同机构内唯一，重复时字段下方红字"该应用名称已存在，请更换" |

| 是否数据同步 | * | 单选 | 否 / 是，默认否 |
| 用户个人信息授权 | * | 单选 | 否 / 是，默认否 |
| 推送地址 | * | 文本框 | 仅是否数据同步=是时展示；校验格式为 http:// 或 https://，必填 |
| TOKEN | * | 只读文本框 | 仅是否数据同步=是时展示；点击右侧「随机生成Token」按钮生成 UUID，最大 50 字符，必填 |

| 适用机构 | * | 多选复选框 | 学校 / 教育局 / 超管后台，至少 1 项；「超管后台」仅桂教通超级管理员登录时展示该选项 |
| 适用学段 | * | 单选+多选 | 范围模式为单选（所有学段/部分学段，默认所有学段）；仅适用机构含"学校"时展示与校验；选"部分学段"时下方展开学段多选：幼儿园/小学/初中/高中/中职/高职/本科/研究生，支持多选，至少 1 项 |

（2）编辑应用（编辑模式）

从 P02b 应用详情页的"修改"链接进入，字段按当前值回填，底部按钮为"提交"和"取消"。

提交时全量校验必填项。校验通过后按应用当前状态分流处理：

- **未上线（app.status = offline）**：修改内容直接覆盖写入 app 记录（app.system_suite_id 不变），立即生效，**不生成审批记录**，toast 提示"保存成功"，返回 P01。
- **已上线（app.status = online）或已上架（listing_status = listed）**：修改内容暂存为「修改待提交」，**此时不生成审批记录**，应用原信息继续对外展示；列表状态标签变为"修改待提交"，操作列出现"提交上线申请"按钮，toast 提示"修改已保存为待提交，请重新提交上线申请，审批通过后生效"，返回 P01。
- **提交上线申请（P02b 上线申请模式下点击「确认上线」）**：此时才生成审批记录（review.type = 修改，review.status = pending），状态标签变为"修改待审批"，toast 提示"上线申请已提交，修改信息待审批通过后生效"。

> 修改生效规则：审批通过前，对外（门户端、机构管理员应用上架管理等）仍展示修改前的旧值；审批通过后系统将暂存的修改内容合并生效，应用保持原有上线 / 上架状态，不重复进入上架列表（listing_status 不变）；审批驳回时修改内容不生效、不清除，机构管理员可调整后重新提交。

#### P02b 应用详情页

页面由面包屑、头部凭证区、基本信息区（上线申请模式下基本信息区下方嵌入「上线配置」区，二者同属一个模块）和底部操作区组成。根据进入入口分为四种模式：管理模式（P01"管理"进入，全部状态应用，应用上线被驳回时展示审批信息）、上线申请模式（P01"上线"进入，offline 或 rejected 应用）、只读查看模式（P01 其他用户"查看"进入）、审批详情模式（P10"详情"进入）。

（1）查看头部凭证区

| 展示项 | 字段 | 形式 |
|-------|------|------|
| 应用 Logo | app.logo | 大尺寸圆角图标，与凭证区左右布局 |
| 应用标题 | app.name + 分类拼接 | 加粗标题 |
| SuiteId | app.system_suite_id | 标签+值两栏，纯只读，全局唯一不可修改 |
| SuiteKey | app.system_suite_key | 标签+值两栏 + 右侧"复制"链接按钮 |

管理模式、上线申请模式显示 SuiteKey「复制」链接；只读查看、审批详情模式展示凭证区但不显示「复制」。凭证创建应用时生成，只读不可更新。

（2）复制 SuiteKey

点击 SuiteKey 右侧"复制"链接，系统将 app.system_suite_key 值写入剪贴板，toast 提示"SuiteKey 已复制"。复制失败（如浏览器权限限制）时 toast 红色提示"复制失败，请手动复制"，页面无其它变更。

（3）查看基本信息区

板块标题为"基本信息（修改的信息需要重新提交上线申请，审批通过后生效）"，右侧提供"修改"链接按钮（仅管理模式显示）。点击"修改"跳转 P02 编辑模式，字段全部回填。应用存在「修改待提交」或「修改待审批」标记时，标题下方展示提示条：待提交时说明"当前修改已保存为待提交，尚未生成审批信息，请重新提交上线申请，审批通过后修改才会生效"并提供「立即提交上线申请」入口；待审批时说明"修改信息正在审批中，审批通过后自动生效，审批通过前按原信息展示"。

基本信息区按 P02 字段分组只读展示：基础信息（Logo 大图/名称/介绍/分类）、打开方式（中文全称，顿号分隔）、跳转登录限制、适用范围（mode=all 显示"所有学段"）、详情介绍（富文本滚动）、应用视频（无则隐藏）、应用属性（生态应用附 suiteID）、数据与授权（数据同步=是时展示推送地址/TOKEN/EncodingAesKey）、收费与可见（按打开方式展示移动端/PC/H5 角色+地址+微信 appid；白名单默认回填三地址、最多 20 个且支持 * 通配符）。只读字段统一以「标签：值」展示，标签后带中文冒号；超长名称截断悬停，介绍富文本自带滚动。

（4）底部按钮

所有底部按钮居中显示。

**管理模式**：仅显示"返回"按钮，操作通过头部 SuiteKey「更新」与基本信息区「修改」入口执行。

**上线申请模式**：应用基本信息区下方（同一模块内）新增可编辑「上线配置」区，提交/返回按钮统一置于模块最下方，显示「提交」（主）+「返回」（次）。点击"提交"前系统核对应用必填字段完整性及上线配置必填项，且须勾选上架承诺书（未勾选时"提交"置灰）；缺项时顶部红色提示"应用信息不完整，请先完善"，阻止提交。校验通过后系统生成 review 记录：首次上线 review.type = 上线；应用存在「修改待提交」内容时 review.type = 修改。review.status = pending，toast 分别为"上线申请已提交，待桂教通超级管理员审批"与"上线申请已提交，修改信息待审批通过后生效"，返回 P01 列表。桂教通超级管理员提交时不生成审批记录（审批为其专属操作），直接置 app.status = online，toast「上线成功」，返回 P01 列表。

上线配置区（上线申请模式）字段及显示逻辑：
- 是否跨机构（radio 是/否，*）：仅低代码应用展示；桂教通超级管理员选"是"时联动展示跨机构层级与所属机构，机构管理员选"是"时不展示这两项。
- 跨机构层级（radio 厅/市/区县，*）：仅桂教通超级管理员 + 低代码应用 + 是否跨机构=是 时显示。
- 所属机构（可搜索多选输入框，*）：仅桂教通超级管理员 + 低代码应用 + 是否跨机构=是 时显示；根据输入机构名称模糊搜索（最多查询 50 条），支持多选；数据来源按跨机构层级获取——层级为厅→获取所有教育行政部门，为市→获取所有市级教育行政部门，为区县→获取所有区县教育行政部门；跨机构层级切换时清空已选并重新加载候选。
- 收费方式（radio 收费/免费，*）：仅非低代码应用展示；选"收费"时联动展示是否可试用、试用套餐、授权套餐。
- 是否可试用（radio 是/否，*）：仅非低代码应用 + 收费方式=收费 时显示；选"是"时展示试用套餐。
- 试用套餐（下拉，*）：仅非低代码应用 + 收费方式=收费 + 是否可试用=是 时显示。
- 授权套餐（下拉多选，*）：仅非低代码应用 + 收费方式=收费 时显示；数据来源应用套餐配置（套餐管理），可多选多条套餐。
- 版本号（下拉搜索框，单选）：仅低代码应用展示；是否跨机构 = 否 时必填（*），是否跨机构 = 是 时非必填；按当前低代码应用ID远程获取版本列表，未获取到则提示"需要上架应用到低代码应用市场"。
- 上架承诺书（checkbox，必勾选）：文案与免责声明弹窗同 P05（禁止点遮罩关闭，仅「我知道了」关闭）；未勾选时「提交」置灰。

该应用已被删除或不属于当前机构时，页面顶部提示"应用不存在或无查看权限"，隐藏所有操作按钮。

（5）查看审批信息

审批详情模式：展示当前应用最近一条上线审批记录（申请类型、审批状态徽标、申请人/时间、审批人/时间、审批意见；字段同 P11v），无记录时整块隐藏。管理模式在 app.status = rejected（上线申请被驳回）或存在修改审批记录（修改待审批 / 修改被驳回）时展示最近一条对应记录，字段相同；其余状态不展示。

#### P04 应用上架管理页

页面由筛选区、结果列表和行内操作组成。

（1）查询上架应用列表

筛选栏提供应用名称、应用分类、上架范围（下拉，本机构的范围列表）。点击"搜索"按条件刷新列表；点击"重置"清空条件恢复默认视图。

列表按创建时间倒序，每页 20 条，展示：应用 Logo、应用名称、应用分类（一级/二级）、是否平台应用（平台型/非平台型，仅桂教通超级管理员列展示）、开发者名称、应用属性（完整属性文本，如"原生应用""原生应用/低代码应用""生态应用"）、上架范围（仅展示上架时「范围选择」所选内容：选择全平台则展示"全平台"，选择按范围则展示所选范围名称，以英文逗号隔开；不展示分享范围。每条范围均为超链接、可单独点击进入对应范围的 P04b 应用安装列表）、创建时间、上架状态（已上架/已下架/未上架标签）。

> 上架记录规则同 P05：一次上架只生成一条记录，上架范围列仅聚合「范围选择」内容、不含分享范围，各范围可点选进入 P04b。

（2）上架应用

listing_status = unlisted 或 dismissed 且 app.status = online 的应用行显示"上架"按钮。点击进入 P05 应用上架配置页。

> 上架范围与分享范围规则见 P05（含学校机构、分享来源、动态引用）。

> 已下架（dismissed）应用重新上架时，保留原上架范围：P05 的上架范围默认回填该应用下架前的上架范围配置，管理员可在此基础上调整，确认后直接进入 listed，不丢失原范围设置。

（3）下架应用

仅 listing_status = listed 时显示"下架"按钮。点击弹出确认框"确认要下架 XXX 吗？下架后全区用户将无法使用此应用，已安装的应用不会被卸载"。确认后 listing_status = dismissed（已下架），仅使应用从范围不可见，不卸载已安装的应用。

> 分享来源应用规则：其他机构分享过来的应用，若分享方在「应用分享管理」中停止分享当前应用，被分享方侧该应用自动变为已下架（listing_status = dismissed），且**不允许重新上架**；该行"上架"按钮仍在，点击时 toast 错误提示「【分享应用的机构名称】已经停止分享当前应用，当前应用不能上架。」，不进入 P05。已安装应用不卸载。
>
> 停止分享范围含**桂教通平台**时规则一致：桂教通平台侧该应用同样自动下架且不可重新上架，点击"上架"提示同上（机构名称取该应用的分享方机构）。

P04 页面顶部以两个 Tab 组织：**应用上架管理**（见上）与**应用分享管理**（当前机构分享给其他机构 / 桂教通平台的应用）。

（4）应用分享管理

展示当前机构已分享给其他机构或桂教通平台的应用，分享范围于上架时记录。

筛选栏提供应用名称、应用分类（下拉）、是否平台应用（下拉：平台型/非平台型）。点击"搜索"按条件刷新列表；点击"重置"清空条件。

列表展示：应用 Logo、应用名称、应用属性（展示应用类型内容，原生应用/生态应用 + 低代码应用/自建应用等）、应用分类（应用对应的分类）、分享范围（记录上架时分享范围，桂教通平台及每个被分享机构均逐一列出，如"桂教通平台、南宁市第一中学、柳州市高级中学、桂林市育才小学、北海市实验学校、玉林市第一初级中学、梧州市实验小学"）、分享时间、操作（停止分享）。

停止分享：点击行内"停止分享"弹出"停止分享"弹窗。弹窗内"停止分享范围"按两类友好承载大量机构，且**至少选择一项（必填）**：
- **桂教通平台**：该应用当前分享至桂教通平台时以勾选框展示，旁注"停止后平台侧该应用下架且不可重新上架"；
- **其他机构**：仅列出该应用已分享的机构，以「搜索框 + 固定高度 220px 滚动复选列表」展示，支持按机构名称实时搜索、全选当前筛选结果、清空已选；列表上方实时展示「已选 X / 共 N 个，单次最多 200 个」。

分享限制最多 200 个机构，因此**单次停止分享同样最多 200 个机构**：勾选超出时保留前 200 个并提示「单次最多停止分享 200 个机构，已保留前 200 个」，提交时超过 200 提示「单次最多停止分享 200 个机构，请分批操作」。

- 低代码版本号已在 P02b 上线申请模式配置，本页不再选择。
- 学校机构：无范围选择，上架范围列展示本校及分享目标，记录在超管与对应机构生成，状态未上架；分享过来的应用上架后不生成分享记录。
- 分享来源应用：若分享方已停止分享当前应用（含停止分享给桂教通平台），被分享方（对应机构 / 桂教通平台）侧该应用保持已下架且不可重新上架，提交上架时提示「【分享应用的机构名称】已经停止分享当前应用，当前应用不能上架。」

（5）启用/停用分类

- 点击"停用"弹窗二次确认"停用后，当前分类及下级分类将停用，请确认是否停用"，确认后当前及所有下级 status = disabled。
- 点击"启用"弹窗二次确认"启用后，当前分类及下级分类将启用，请确认是否启用"，确认后当前及所有下级 status = enabled。

（6）删除分类

仅已停用（status = disabled）的分类行显示"删除"按钮。已启用分类不显示删除按钮。

删除限制：已被应用使用的分类不可删除；存在下级分类的分类不可删除（需先删除其下级分类，且下级分类均无应用使用）。

满足删除条件时，点击"删除"弹窗二次确认"数据删除后，无法找回，请确认是否继续删除？"，确认后删除该分类。

（6）数据实时性 / 刷新频率

统计采用"实时 + 准实时（分钟级）"混合模式，不做 T+1，所有指标在"今日"周期下即可查看当日数据：

- **刷新时机**：进入页面、切换时间范围（今日/本周/本月/本年）、切换角色时实时向后端拉取最新统计数据；页面提供「刷新」按钮，点击后重新拉取全部区块数据；不做自动轮询。
- **实时指标（秒级）**：应用安装数、平台应用数/机构应用数、应用分类统计、活跃/非活跃应用占比——基于应用/机构/上架等基础业务表实时聚合。
- **准实时指标（最长延迟 5 分钟）**：应用点击量趋势、应用使用人数、活跃应用数、用户数量榜 Top10、应用安装排行榜 Top10——基于点击/使用/安装行为流水，按 5 分钟粒度窗口汇总落库，页面展示最近一次聚合结果。
- **历史周期数据**：本周/本月/本年由日汇总表累加，已结算日期数据固定，当日部分按上述实时/准实时口径展示。
- **数据一致性**：同一时刻结构类与行为类指标可能存在最长 5 分钟时间差，属正常现象；导出数据与页面展示同源、口径一致。

### 5.3 字段级权限例外

字段级角色差异已并入对应页面需求（P02 / P02b / P05 / P08 / P17），本节不重复。共性结论仅四类存在角色差异：

1. **「是否平台应用」字段**：平台型仅桂教通超级管理员可选且必填；机构管理员新增固定为非平台型，字段不展示（P02、P02b）。
2. **「跨机构层级 / 所属机构」字段**：仅桂教通超级管理员可选；机构管理员不展示（P02b、P05）。
3. **「上架范围 / 分享范围」**：学校机构管理员不展示上架范围、默认本校；分享范围仅机构管理员可配置（平台角色无本机构归属，不涉及分享范围），被分享应用不展示（P05、P08）。
4. **「统计范围 / 导出范围」**：平台角色统计全平台（仅含平台应用与平台管理的机构应用，独立机构不计入），机构管理员仅本机构；导出需具备查看权限（P17）。

推送地址 / TOKEN / EncodingAesKey（是否数据同步=是）、suiteID（应用属性=生态应用）、应用ID（应用属性=低代码应用）、可见性地址（打开方式含对应方式）等属字段间业务联动，非角色权限差异，不在此列。

## 七、状态机

### 7.1 应用上下线状态

| 状态 | 含义 | 操作人 | 触发动作 | 下一状态 | 限制条件 |
|------|------|--------|----------|----------|----------|
| offline | 未上线，不可上架 | tenant_admin | 提交上线审批 | online / rejected | 审批通过变为 online；审批驳回变为 rejected |
| offline | 未上线，不可上架 | platform_admin | P02b 上线申请模式提交（免审批） | online | 审批为超管专属操作，提交即上线，不生成 review 记录 |
| rejected | 已驳回 | platform_admin | 重新提交上线申请（免审批） | online | 直接置 online，不生成 review 记录 |
| rejected | 已驳回，上线申请被驳回，不可上架 | tenant_admin | 重新提交上线审批 | offline（审批中）/ online | 重新提交后回到 offline（列表展示待审批）；审批通过变为 online |
| online | 已上线，可进行上架 | tenant_admin | 下线 | offline | 未上架时允许下线；已上架时隐藏下线按钮 |

### 7.2 应用上架状态

| 状态 | 含义 | 操作人 | 触发动作 | 下一状态 | 限制条件 |
|------|------|--------|----------|----------|----------|
| unlisted | 未上架，范围中不可见 | tenant_admin | 上架配置 | listed | app.status 必须为 online；需配置上架范围；须勾选上架承诺书（未勾选时确认上架置灰） |
| listed | 已上架，范围中可见 | tenant_admin | 下架 | dismissed | 二次确认："下架后全区用户将无法使用此应用，已安装的应用不会被卸载" |
| listed | 已上架，范围中可见 | platform_admin | 强制下架（P06） | dismissed | 二次确认："确定要强制下架【{app.name}】吗？下架后该应用在【{app.tenant_name}】的上架列表将变为已下架状态，已安装的应用不卸载。"；仅超管可操作；写 OperationLog（force_delist） |
| dismissed | 已下架，范围中不可见，已安装应用不受影响 | tenant_admin | 上架配置 | listed | 可重新上架，且重新上架时保留原上架范围（P05 默认回填下架前的范围配置） |

应用必须先上线（online）后才可上架（listed）。已上架不允许直接下线，必须先下架方可下线。

> 修改态标记（editState，仅用于列表展示，不改变 app.status）：已上线 / 已上架应用编辑保存后 editState = pending_submit（修改待提交），此时不生成审批记录；重新提交上线申请后 editState = pending_review（修改待审批）；审批通过后清除标记并将修改内容合并生效，驳回后回到 pending_submit。未上线应用的编辑不产生该标记，保存即生效。

> 范围动态引用不影响状态：标签或范围内机构的增删仅改变应用的上架范围（可见机构集合），应用上架状态（listing_status）不变，仍在范围内的机构继续可见，不在范围内的机构不可见该应用；已安装应用不卸载、无需重新审核。

### 7.3 审批记录状态机

| 状态 | 含义 | 操作人 | 触发动作 | 下一状态 | 限制条件 |
|------|------|--------|----------|----------|----------|
| pending | 待审批（上线） | tenant_admin | 提交上线申请 | — | 仅 app.status = offline / rejected 且无待提交修改时生成 |
| pending | 待审批（修改） | tenant_admin | 已上线 / 已上架应用编辑保存后，重新提交上线申请 | — | 编辑保存本身不生成记录，提交上线申请时才生成；审批通过前对外仍展示旧值 |
| pending | | platform_admin（桂教通超级管理员） | 审批通过 | approved | — |
| pending | | platform_admin（桂教通超级管理员） | 驳回 | rejected | 驳回原因必填 |
| approved | 审批通过；上线类型进入上架列表，修改类型的新值此时生效 | — | — | — | 终态；上线：app.status 变为 online 并进入上架列表（listing_status = unlisted）；修改：保持原有上线 / 上架状态，不重复进入上架列表 |
| rejected | 审批驳回 | tenant_admin | 重新提交 | pending | 上线类型 app.status 变为 rejected；修改类型修改内容不生效，回到「修改待提交」可再次提交 |

> 桂教通超级管理员提交上线申请时不生成 review 记录，直接置 app.status = online（审批为超管专属操作，不存在自我审批）；其余规则同机构管理员。
### 7.4 订单状态机

| 状态 | 含义 | 操作人 | 触发动作 | 下一状态 | 限制条件 |
|------|------|--------|----------|----------|----------|
| pending | 待支付 | 系统生成 | 用户下单 | — | 用户在商城完成下单时生成 |
| pending | | 商城系统 | 支付回调 | paid | 商城支付完成回调后自动变更 |
| pending | | 系统 | 超时取消 | cancelled | 超过支付有效期未支付时自动变更 |
| paid | 已支付 | 系统 | 授权到期 | expired | 授权有效期到达后自动变更（套餐有效期到期） |
| expired | 已过期 | — | — | — | 终态；授权有效期到达后从 paid 自动流转 |
| cancelled | 已取消 | 用户 | 取消订单 | — | 仅 pending 状态下可取消；paid 状态不可取消 |
| paid | 已支付 | tenant_admin（机构管理员） | 申请退款 | refund_pending | 仅 paid 状态可申请；退款工单提交后同步至桂教通超级管理员待审批队列 |
| refund_pending | 退款中 | platform_admin（桂教通超级管理员） | 审批通过 | refund_success | 审批意见选填；通过后触发原路退款，订单状态置为退款成功 |
| refund_pending | 退款中 | platform_admin（桂教通超级管理员） | 审批驳回 | refund_rejected | 驳回原因必填；驳回后订单回到 paid，可重新发起退款 |
| refund_rejected | 退款驳回 | tenant_admin（机构管理员） | 重新申请退款 | refund_pending | 修改后可重新发起退款申请 |

> 退款通过后应用回到购买前状态：refund_pending 经审批通过（→ refund_success）后，对应应用回到购买前状态——购买前已安装则保持已安装状态，未安装则保持未安装状态，不强制从「我的应用中心」移除，点击应用打开应用详情页（P22），根据状态展示「购买/安装」按钮，即整体回到用户购买前的可使用状态；订单保留 refund_success 终态以留痕审计。
